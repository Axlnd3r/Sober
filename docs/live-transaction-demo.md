# Live Panta transaction demo

Run `npm run verify:connections`, `npm run probe:panta`, then `npm run demo:preflight` from the project root. The preflight reads the local room database and Panta catalog without asking for a quote or sending a transaction. To check a specific wallet's positions and claim eligibility, run `npm run demo:preflight -- --wallet <public Solana address>`. No private key is needed.

The local `.env.local` used on 9 October 2026 has `TRADING_ENABLED`, `CREATE_ENABLED`, and `CLAIMS_ENABLED` set to `true`. That file is ignored by Git, so a deployment needs its own explicit settings. Panta, PostgreSQL, and both configured RPC endpoints passed read-only checks. Panta reported market-creation permission for this account. These results do not prove that a wallet can sign or that any transaction will confirm.

Run `npm run setup:admin-wallet` to validate or create a local admin wallet and print its public address. Its private key is stored only in ignored `.sober-admin-wallet.local.json` under `secretKeyBase58`. To use it in a browser, privately import that value as a **Solana private key** into Phantom: profile avatar → Add Account → Import Private Key. Follow [Phantom's official import steps](https://help.phantom.com/articles/add-accounts-or-import-wallets-into-phantom-after-initial-setup-28355310978067). Never paste the key into a chat, issue, screenshot, or recording. The 9 October read-only check found **0 SOL, 0 USDC, and 0 Panta positions** at the local address. Fund it only after reviewing a Panta fee or buy quote; imported private-key accounts must be backed up separately from Phantom's primary recovery phrase.

## Rehearsal sequence

1. Open `http://localhost:3000` and show live Panta discovery, price timestamps, and a saved pre-match forecast. Connect a browser wallet and approve the separate sign-in message to save a live notebook record.
2. To show creation, open `/admin` with the wallet in `ADMIN_WALLET_ALLOWLIST`. Select the reviewed unmapped draft, provide a permanent public image URL, and choose an opening time, closing time no later than the room cutoff, and a later resolution time. Request Panta's fee quote and inspect the returned amount and expected event. The unsigned build can be requested next. Only press **Sign and send creation** if the wallet owner accepts the displayed debit and market terms. After confirmation and Panta registration, review the returned market again, publish the room, and resume trading.
3. For a primary market that matches a published room, open the room and check the fresh Panta phase. Choose YES or NO, request a quote, inspect the USDC amount, fee, shares, and expiry, then build. The wallet owner may approve **Sign and send**. Show the resulting signature, chain confirmation, Panta verification, and indexed position separately. Do not repeat an uncertain broadcast; use **Check status**.
4. Open `/positions`. A win claim is available only after Panta reports `claimable=true` on a mapped market for that wallet. The claim build and wallet approval are separate. A newly purchased position cannot be claimed immediately, and the 17 October fixture will not settle before the 12 October hackathon submission deadline.

For the current submission recording, show the live read-only market feed and forecast/notebook flow, then show a clearly labeled transaction review only if an eligible room and wallet are actually available. A disabled button or an unsigned build is not evidence of a completed purchase, creation, or claim. The [Panta quickstart](https://github.com/Kaito-HQ/panta-api-pub/blob/main/quickstart.mdx) describes the quote → build → sign → broadcast → submit/verify path and the separate claim eligibility check.

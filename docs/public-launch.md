# Put Sober online

Sober needs a Next.js server, PostgreSQL, a server-side Panta key, and an exact HTTPS origin for wallet sign-in. The GitHub repository alone does not serve the application. The current local database and `.env.local` are not deployed or copied by Git.

## Provision

1. Create a Vercel account and import `Axlnd3r/Sober` as a Next.js project. Keep Node.js at 24.x. Vercel supports Git-connected deployments and Node.js 24.
2. Provision PostgreSQL through Vercel's Marketplace, for example Neon. Use a **pooled** PostgreSQL connection string for the app's `DATABASE_URL`; use a direct connection for migrations. Vercel's former first-party Postgres product is no longer offered for new projects.
3. Set production environment variables in Vercel, not in GitHub or source files. Use `.env.example` as the list. Required for the first public live version: `APP_MODE=live`, `APP_URL` set to the exact final `https://...` origin, `DATABASE_URL`, `PANTA_API_KEY`, `SOLANA_RPC_URL`, `NEXT_PUBLIC_SOLANA_RPC_URL`, `SOLANA_NETWORK=mainnet-beta`, `PANTA_EXPECTED_GENESIS_HASH`, `PANTA_PROGRAM_IDS`, `PANTA_USDC_MINT`, and a public `ADMIN_WALLET_ALLOWLIST` address. The browser RPC URL must be permitted for public use and must not contain a private token. Start with `TRADING_ENABLED=false`, `CREATE_ENABLED=false`, and `CLAIMS_ENABLED=false` on the public deployment until its own wallet flows are verified. Do not copy the local `.env.local` wholesale.
4. Run `npm run check:production` with those production variables in the process environment. It reports missing names and invalid structure without printing values. Run `npm run verify:connections -- --env-only` in a trusted terminal with the remote variables loaded to check the database, Panta account endpoint, and both RPC genesis hashes. Neither check deploys the app.
5. Apply `db/migrations/0001` through `0007` to the new database before inviting users. From a trusted terminal, set `DATABASE_URL` to the **direct** remote connection string and `MIGRATION_HOST_CONFIRM` to its exact hostname, then run `npm run db:migrate:remote`. The script refuses localhost and a missing/mismatched hostname confirmation. Do not paste the database URL into chat, logs, or a committed file.
6. Deploy the production branch. `GET /api/health` must return `status: ready`, `mode: live`, and `database: connected`. Check `/`, `/markets`, `/matches`, wallet sign-in, and one free forecast. The market catalog may be available while no reviewed football room is published.
7. Connect the allowlisted admin wallet at `/admin`. Import or create an upcoming fixture, check the source, question, rule and result source, then use **Review fixture and rules** and **Publish reviewed room**. This makes the free forecast and notebook available without inventing a Panta market. A later exact Panta mapping remains paused for trading until separately reviewed. Never map a different question merely to expose a buy button.

`FOOTBALL_API_KEY`, `GROQ_API_KEY`, and `JOB_SECRET` are optional for initial market discovery and free forecasts. Without the football key, imported-fixture sync does not run; manually reviewed fixture dates need rechecking. Without Groq, Match Analyst cannot generate new analyses. Without a scheduler, the authenticated job endpoints remain available but do not run automatically. Buy, create, and claim still depend on eligible Panta state, a funded browser wallet, and user approval.

## Before sharing the URL

Use the public production URL in `APP_URL`, then redeploy after any environment change. Confirm that wallet login produces a session cookie, forecast saves return a server-captured context, and a second wallet cannot read the first wallet's notebook. Check the room and market phase shortly before filming. Run `npm run demo:preflight -- --wallet <public-address>` only against the desired environment; by default it reads local `.env.local`, so it is a local check until adapted for remote configuration. Keep the private admin key, Panta account file, and database credentials off the public repository.

Vercel deployment and environment guidance: [Git deployments](https://vercel.com/docs/git), [environment variables](https://vercel.com/docs/environment-variables), [Node.js versions](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions), [Postgres Marketplace](https://vercel.com/docs/postgres).
